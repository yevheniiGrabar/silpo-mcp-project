# 00 · Overview — «Останній Шанс» (Last-Chance Engine)

> ПРОДУКТ ПРОЄКТУ (актуальний, після півоту). Meal-planner (старі docs 01-05,08) — LEGACY, не будувати. Джерело істини по продукту: цей файл + `CONCEPT-LAST-CHANCE.md` + `PITCH-LAST-CHANCE.md`. Механіка MCP — `06-MCP-VERIFIED.md`. Що будувати — `LC-BUILD.md`. Порядок — `LC-PHASES.md`.

## 1. Що це
AI-агент у екосистемі Сільпо, який **автоматизує рутину, яку гість і так робить вручну** — розбирає його бонуси/купони/промо за термінами згорання — і збирає персональну пропозицію, де **бонус/купон, що згорає, оплачує супер-ціну на ЙОГО звичний товар**. Персонально (мій бонус × мій товар × зараз), в один тап. Канал — **Telegram-бот** + **B2B-дашборд** категорійним менеджерам.

## 2. Killer-властивість
Економія гостя = **пряме скорочення двох статей збитку Сільпо** одночасно: непогашене купонне/бонусне зобовʼязання (breakage) + списання near-expiry товару. Тому цінність **рахується на живих даних MCP**, а не обіцяється.

## 3. Позиціонування (жорстко)
- Подавати як **ОСОБИСТУ вигоду**: «твій бонус + супер-ціна на твій звичний товар, поки не згоріло». **НЕ** «врятуй товар зі списання» (репутаційний барʼєр рітейлу).
- Пушити **тільки товари з привичної корзини** (`get_my_offline_orders`) — urgency підсилює наявний намір.
- UX = **один тап**, без екранів з умовами.

## 4. Архітектура
```
Гість (Telegram) ─► Laravel BFF (агент + детермінований матчинг + токени server-side) ─► mcp.silpo.ua
Категорійний менеджер (web-дашборд) ─┘
```
- Backend: PHP 8.3+, Laravel, `laravel/ai`+`laravel/mcp` (АБО raw JSON-RPC-клієнт — фолбек, вже перевірений).
- Головний канал: **Telegram-бот**. Опційно: **B2B web-дашборд** (Blade/Livewire або простий SPA).
- Мобільного Flutter-застосунку НЕ треба (TG-бот дешевший і переконливіший для демо).

## 5. Перевірено наживо (докази механіки — `06`)
- `get_my_coupons` віддає купон з `beginDate/endDate` → **«перший дедлайн» реальний** (знайдено купон endDate 2026-08-17).
- `get_products(mustHavePromotion,inStock)` → 57/60 з `oldPrice`; глибина уцінки рахується, наживо до −52% → **«другий дедлайн»-proxy реальний**.
- `get_loyalty_info` → баланс бонусів. `get_my_offline_orders` → історія (звичні товари).
- ⚠️ `get_my_certificates` → 500 на тесті (фолбек). Кошик не створюється через MCP (лише активний + checkout-лінк).

## 6. 6 критеріїв журі → де закриваємо
| Критерій | Де |
|---|---|
| 01 Офіційний MCP | ядро на mcp.silpo.ua, ~13 tools |
| 02 Агентний сценарій | ланцюг: стимули→уцінки→історія→матчинг→кошик→checkout |

| 05 Інтеграція | «Власний Рахунок»/TG + B2B-дашборд (прецедент «Каса вражень») |

## 7. Обмеження (не порушувати)
near-expiry = proxy (глибокі уцінки; справжні дати — внутр. фід Сільпо); breakage-конфлікт виносити відкрито; MCP без історичних цін → не «інфляція/окупність»; safe-default — нічого не купується без явного тапу; демо-акаунт потрібен з непорожніми купонами+історією.
