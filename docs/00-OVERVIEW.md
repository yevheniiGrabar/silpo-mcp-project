# «Розумний кошик» — Overview & Architecture

> Hackathon **Сільпо AI Factory** · призовий фонд 100 000 ₴ · реєстрація до **31 серпня 2026** · розробка 1–14 вересня · фінал 30 вересня.
> Цей пакет документів — детальне ТЗ для AI-агента-виконавця. Читати по порядку: `00` → `01` → `02` → `03` → `04` → `05`.

---

## 1. Продукт (одним абзацом)

Мобільний застосунок, який планує меню на тиждень і збирає готовий кошик Сільпо **з максимальною користю за бюджет гостя**. Гість обирає філію, бюджет, уподобання, алергії та кухонну техніку — AI-агент будує меню **навколо сьогоднішніх акцій Сільпо**, підбирає під нього реальні товари, укладається в бюджет (акції + купони + вигідні заміни) і показує реальну економію поруч зі «звичайним» кошиком. Окремо — проактивні рекомендації з історії покупок («у п'ятницю ти зазвичай береш…»). На виході — кошик на оформлення (самовивіз/доставка). **Оплату в застосунку НЕ беремо** — віддаємо checkout-лінк Сільпо.

## 2. Ключові рішення (не міняти без причини)

| Рішення | Чому |
|---|---|
| **Два режими** (гість обирає): «Економний» vs «Смачніше» | Обслуговуємо обидва сегменти; преміум-режим = вищий чек для Сільпо (знімає страх канібалізації маржі) |
| **Режим «Економний» = promotion-first**: меню будується від `get_promotions`, жорсткий бюджет | Дифереціатор проти «5 однакових корзинок»; рухає акційний товар; для обмеженого бюджету |
| **Режим «Смачніше» = preference-first**: м'який бюджет (+10–30%), акції — бонус | Для тих, хто готовий витратити більше; менше даунгрейдів, бренди/фреш, апселл |
| **«Максимум користі за бюджет», НЕ «найдешевше»** | Знімає страх журі-продактів про канібалізацію маржі; пріоритет акційних/private-label SKU у Економному режимі |
| **Дві корзини поруч + лічильник економії** | Робить економію доказовою: відповідь на «зекономлено відносно чого?» |
| **Детермінований оптимізатор і матчинг у бекенді, НЕ в LLM** | LLM галюцинує граммовки/ціни; код дає стабільний, відтворюваний результат |
| **Рекомендації з історії покупок** («патерн п'ятниці») | Killer-фіча; збігається з критерієм «персональні рекомендації» |
| **Токени Сільпо — серверно** | Обов'язкова вимога хакатону |
| **MCP у центрі кожного екрана** | Дискваліфікація, якщо AI лише генерує текст без MCP |

## 3. Архітектура

```
┌─────────────────┐      HTTPS/JSON        ┌──────────────────────────┐   MCP (JSON-RPC/HTTP)   ┌──────────────────┐
│  Flutter app    │ ─────────────────────► │  Laravel BFF (backend)   │ ──────────────────────► │  mcp.silpo.ua/mcp │
│ (iOS/Android)   │ ◄───────────────────── │  laravel/ai + laravel/mcp│ ◄────────────────────── │  (39 tools)       │
└─────────────────┘                        │  + Anthropic (Claude)    │                         └──────────────────┘
     UI, стан                              │  токени Сільпо server-side│         auth.silpo.ua (OAuth 2.1 + PKCE)
                                           └──────────────────────────┘
```

- **Flutter** ніколи не ходить у MCP напряму й ніколи не тримає токен Сільпо. Тільки → наш Laravel.
- **Laravel BFF** тримає токени, оркеструє Claude через `laravel/ai`, викликає інструменти Сільпо через MCP-клієнт `laravel/mcp`, рахує детермінований матчинг + бюджет.
- **Claude (Anthropic)** — тільки планування меню + пояснення замін. Оптимізацію рахує код.

## 4. Стек

**Backend:** PHP 8.3+, Laravel 12 (перевірити констрейнт `laravel/ai`/`laravel/mcp`; якщо треба — 13), MySQL 8, Redis (черги/кеш), `laravel/ai`, `laravel/mcp`, Anthropic provider.
**Frontend:** Flutter (stable, ≥ 3.24), Dart 3, Riverpod, dio, freezed, go_router, flutter_animate.
**Хостинг демо:** будь-який (Railway/Fly/AWS) — для хакатону досить одного інстансу + керований MySQL/Redis.

## 5. Критерії журі → де закриваємо

| Критерій | Де в проєкті |
|---|---|
| Цінність гостю/бізнесу | економія + basket completeness + retention (`03`, екрани S2/S5/S6) |
| Якість MCP-інтеграції | 10+ tools, повний цикл, видимий JSON-RPC лог (`01`, `02`) |
| «Розумність» агента | planner-агент + constraint-оптимізатор (`02`) |
| Реалістичність вбудування | фіча всередині застосунку/лояльності Сільпо, без сторонніх API |
| Прототип/демо | робочий застосунок + live лог викликів на екрані генерації (`05`) |
| Валідація + масштабування | 3–5 реальних меню + слайд масштабування (`05`) |
