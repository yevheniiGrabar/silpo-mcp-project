# 02 · AI-агент — які агенти, як використовуємо Claude, промпти

> Головна ідея: **LLM робить лише те, що добре робить** — планує меню й пояснює заміни людською мовою. Усе, де важлива точність чисел (матчинг SKU, ціни, вкладання в бюджет), робить **детермінований код** (див. `01`, §4). Це навмисно — щоб демо не розсипалось на галюцинаціях.

---

## 1. Агенти в системі

| Агент | Тип | Роль | Викликає MCP? |
|---|---|---|---|
| **MealPlannerAgent** | `laravel/ai` Agent (Claude) | Будує меню тижня від акцій + профілю; декомпозує страви в інгредієнти з кількостями | ✅ читає `get_promotions`, `get_my_food_restrictions`, `get_my_family` (через tools) |
| **SubstitutionExplainerAgent** | Claude (можна той самий агент, окремий промпт) | Пише людське пояснення кожної заміни («дешевше на 12 ₴, акція до п'ятниці») | ❌ отримує дані від оптимізатора |
| **BudgetOptimizer** | ❗ НЕ LLM, звичайний PHP-сервіс | Матчинг + вкладання в бюджет + купони | ✅ `find_products_batch`, `get_replacements`, `get_my_coupons` (детерміновано) |
| **RecommendationAgent** (опц.) | Claude, легкий | Формулює картку «патерн п'ятниці» приємним текстом | ❌ дані від `RecommendationService` |

> Для хакатону достатньо **одного** налаштованого агента (`MealPlannerAgent`) + оптимізатора-коду. Explainer/Recommendation можна зробити другим викликом того ж провайдера.

## 2. Як під'єднати Claude + MCP через `laravel/ai`

Модель: **claude-opus-5** (або claude-sonnet-5 для швидшого/дешевшого демо — під час прогонів обрати за якістю/латентністю).

```php
use Laravel\Ai\Agent;                // уточнити namespace у доці пакета

$agent = Agent::make()
    ->using('anthropic', 'claude-sonnet-5')   // провайдер/модель
    ->system($mealPlannerSystemPrompt)         // див. §3
    ->tools([
        ...$silpoMcp->toolsFor($user),         // MCP-tools Сільпо йдуть у той самий масив
    ]);

$response = $agent->respond($userPrompt, [
    'response_format' => MealPlanSchema::class, // структурований JSON-вихід
]);
```

Ключове: **інструменти Сільпо кладуться прямо в `tools()`** поряд зі своїми — `laravel/ai` сам переводить MCP-схему, викликає віддалений tool, коли модель просить, і нормалізує відповідь. Агентну петлю руками не пишемо.

**Обмеження tools для planner-агента:** дати лише читальні tools, потрібні для планування — `get_promotions`, `get_my_food_restrictions`, `get_my_family` (+ опц. `get_categories`). НЕ давати агенту `add_to_cart`/`find_products_batch` — матчинг і кошик робить код, щоб уникнути галюцинацій цін.

## 3. System prompt для MealPlannerAgent (чернетка, укр.)

```
Ти — кулінарний планувальник у застосунку «Розумний кошик» для мережі Сільпо.
Твоє завдання: скласти меню на тиждень (7 днів × 3 прийоми: сніданок, обід, вечеря)
під обмеження гостя, максимально використовуючи товари, що СЬОГОДНІ в акції.

ПРАВИЛА:
1. Врахуй РЕЖИМ (mode), який передається у вхідних даних:
   - mode=economy: спочатку виклич get_promotions і будуй меню НАВКОЛО акційних товарів —
     це головна цінність. Обирай прості, бюджетні страви.
   - mode=quality: пріоритет — смак, різноманіття й уподобання гостя. Акції (get_promotions)
     враховуй як приємний бонус, але НЕ підлаштовуй усе меню під них. Можна цікавіші/якісніші страви.
   У будь-якому режимі виклич get_promotions, щоб знати, що зараз вигідно.
2. Строго дотримуйся алергій та дієти (get_my_food_restrictions). Жоден інгредієнт
   не має містити алерген. Стиль харчування:
     - pp: збалансовано, менше цукру/смаженого;
     - protein: більше білка;
     - veggie: більше овочів, менше м'яса;
     - budget: прості дешеві базові продукти;
     - surprise: цікаві, незвичні, але реалістичні страви з доступних у Сільпо продуктів.
3. Враховуй склад сім'ї (get_my_family) для розміру порцій та кількості людей.
4. Готуй лише на доступній техніці (передається у вхідних даних, напр. плита+духовка).
   НЕ пропонуй страви, які потребують відсутньої техніки.
5. Дотримуйся ліміту часу на страву (напр. до 60 хв).
6. НЕ вигадуй ціни, граммовки в грошах чи назви конкретних SKU Сільпо — це зробить
   система далі. Твоя граммовка — лише кулінарна кількість інгредієнта (напр. "курка 500 г").
7. Поверни СТРОГО у форматі MealPlanSchema (JSON). Без зайвого тексту.

ФОРМАТ ІНГРЕДІЄНТІВ:
   Для кожної страви — список інгредієнтів з полями: name, qty, unit (g/ml/pcs).
   Назви — простими загальними словами українською ("куряче філе", "рис", "помідор"),
   без брендів, щоб система знайшла реальний товар.
```

**User prompt (динамічний, збирає бекенд):**
```
Режим: {mode} (economy=жорсткий бюджет навколо акцій / quality=смак важливіший, бюджет м'який).
Філія: {branch_name}. Людей: {people}. Бюджет-орієнтир: {budget} ₴/тиждень{quality: + до {budget_flex_pct}% зверху дозволено}.
Стиль: {diet_style}. Алергії: {allergies}. Техніка: {appliances}.
Ліміт часу на страву: {max_cook_minutes} хв.
Склади меню на 7 днів згідно з правилами. Спочатку перевір сьогоднішні акції.
```

> Для **демо** зменшити обсяг: 5–7 вечер замість повних 21 прийому — менше інгредієнтів (~25–30), швидше, менше точок відмови.

## 4. Структурований вихід — MealPlanSchema

```
MealPlan {
  days: [
    { weekday: 1..7,
      meals: [
        { type: "breakfast|lunch|dinner",
          title: string,
          cook_minutes: int,
          appliances: [string],
          ingredients: [ { name: string, qty: number, unit: "g|ml|pcs" } ]
        }
      ]
    }
  ]
}
```
`laravel/ai` `response_format` → валідований об'єкт (модель ретраїть при невідповідності). Далі бекенд агрегує однакові інгредієнти по всьому тижню перед матчингом.

## 5. SubstitutionExplainer — промпт (короткий)

Викликається ПІСЛЯ оптимізатора, отримує факти (стара позиція, нова, різниця ₴, причина: акція/private-label/аналог) і повертає 1 рядок людською мовою.

```
System: Ти пояснюєш заміни товарів у кошику коротко й дружньо, українською.
Один рядок на заміну. Формат: "<що> → <на що>: <вигода> (<причина>)".
Не вигадуй чисел — використовуй лише передані значення.
User: {json фактів заміни}
```

## 6. Чому саме так (для захисту перед журі)

- **Розумність агента** = не «згенеруй список», а constraint-планування під акції + реальна оркестрація MCP.
- **Надійність** = ціни/матчинг/бюджет детерміновані → демо відтворюване.
- **Прозорість** = кожна заміна пояснена → знімає бар'єр довіри.
- **MCP у центрі** = агент реально читає акції/профіль, оптимізатор реально читає товари/купони, кошик реально збирається в Сільпо.

## 7. Definition of Done (agent)
- [ ] MealPlannerAgent повертає валідний MealPlanSchema під усі 5 стилів.
- [ ] Меню жодного разу не містить алергенів (тест на кількох профілях).
- [ ] Меню будується від акцій (перевірити: акційні продукти реально з'являються у стравах).
- [ ] Explainer дає читабельні пояснення без вигаданих чисел.
- [ ] Жодних цін/SKU від LLM — тільки від коду.
