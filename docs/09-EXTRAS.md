# 09 · Нові фічі — калорійність, заміна страв, підписка

> Доповнення до meal-planner (docs 01-05,07). Три додавання, які замовник вибрав: калорії/БЖУ, заміна страви, freemium-підписка.

## 1. Калорійність / БЖУ на страву
**Що:** для кожної страви меню показуємо ккал + білки/жири/вуглеводи; для дня і тижня — сума.
**Як:**
- Джерело — **своє** (Silpo MCP не гарантує структурований склад). Базово: `MealPlannerAgent` при генерації повертає для кожної страви оцінку ккал/БЖУ (додати в `MealPlanSchema` поля `calories`, `protein`, `fat`, `carbs`). Промпт: «оціни калорійність і БЖУ на порцію реалістично; познач це як оцінку».
- Стретч (точніше): `NutritionService` мапить нормалізовані інгредієнти → нутрієнт-база (USDA FoodData / Nutritionix / Edamam), сумує по стравах. Кеш.
**БД:** `meal_plan_meals` + `calories, protein, fat, carbs, nutrition_source(llm|db)`.
**UI (Flutter):** бейдж ккал на картці страви; підсумок дня/тижня; фільтр «ціль по калоріях» у майстрі (опц.).
**Чесність:** позначати «≈ оцінка», не медична порада.

## 2. Заміна страви («не подобається → заміни»)
**Що:** тап «Замінити» на будь-якій страві → агент генерує альтернативу під ТІ САМІ обмеження (бюджет, калорії, дієта/алергії, техніка, режим) → перематчує товари → перераховує список і калорії.
**Як (це і є «живе ре-планування»):**
- `POST /api/meal-plans/{id}/meals/{meal}/swap` → `MealSwapService`:
  1. LLM генерує 1 нову страву під ті самі обмеження (виключити поточну + вже показані альтернативи).
  2. Детермінований матчинг інгредієнтів → SKU (ре-ранкінг як у B3).
  3. Перерахунок бюджету/калорій; оновити `meal_plan_meals`, `cart_items`.
- Тримати `alt_options`/лічильник показаних, щоб не повторювати.
**UI:** кнопка «↻ Замінити» + причина («дешевше / менше калорій / інший смак»); анімований перерахунок суми й калорій.
**Це killer-момент demo:** заміна вживу на сцені = агентність, яку не спишеш на відео.

## 3. Freemium-підписка (монетизація)
**Модель:**
- **Free:** 1 згенероване меню на тиждень; базовий список; без калорій і без заміни.
- **Paid (~4-8$/міс, річний дешевше):** безліміт меню, калорії/БЖУ, заміна страв, профілі сімʼї/алергій, історія, експорт.
**Біллінг (обрати одне):**
- Веб-підписка: **Creem** (просто, вже в досвіді) / Stripe / Paddle (Paddle = merchant of record, знімає податки).
- Україна: Fondy / WayForPay / LiqPay / monobank acquiring.
- Мобільні стори: обовʼязковий IAP (Apple/Google 15-30%) → часто підписку оформлюють на вебі, у застосунку лише логін.
**Реалізація (Laravel):**
- `plans` (code, price, interval, features json), `subscriptions` (user_id, plan_id, status, current_period_end, provider, provider_sub_id).
- Вебхуки провайдера → оновлення статусу.
- **Gating:** middleware/policy `requiresPlan('pro')` на платні ендпоінти (calories, swap, unlimited generate). Ліміт free — лічильник меню/тиждень.
- Feature-flags у профілі → Flutter показує paywall на платних діях.
**UI (Flutter):** екран підписки (плани, ціни), paywall-модалка на платній дії, стан підписки в профілі.
**⚠️ Юридично:** підписка ПОВЕРХ Silpo MCP комерційно — потрібна згода Сільпо (MCP їхній). Для хакатону/MVP демонструємо; для реальних продажів — узгодити з Сільпо АБО відвʼязати джерело цін (мультирітейл/скрейпінг/без цін). Заклали архітектурно: `PriceSource` — інтерфейс, Silpo — одна з реалізацій, щоб замінити пізніше без переписування.
