# AGENT-LITE — легкий агентний план під хакатон (Claude + Silpo MCP + Telegram + тригери)

> РЕКОМЕНДОВАНИЙ шлях для хакатону: тонкий розмовний агент замість важкого Laravel+Flutter. Менше коду, швидше до робочого demo, точно в категорію «Агенти що виконують завдання» + «Зовнішні інтеграції (месенджери/AI-платформи через MCP Сільпо)».
> Важкий продуктовий варіант (Laravel+Flutter) — docs 00-09, лишається як «product/vision».

## 1. Суть
Один розмовний агент на Claude, під'єднаний до Silpo MCP (реальні дії) + канали (Telegram, і/або Claude напряму) + планувальник для проактивних тригерів. Гість пише/говорить — агент виконує послідовність дій і віддає checkout-лінк.

## 2. Архітектура (мінімальна)
```
Гість (Telegram / Claude Desktop) ─► Агент (Claude Agent SDK + system-prompt + tools)
                                          ├─► Silpo MCP (пошук/акції/кошик/checkout)
                                          └─► Telegram send (відповіді, пуші)
Планувальник (cron / Claude Routine / n8n) ─► тригерить агента ─► Telegram-пуш («час готувати / час замовити»)
```
Без окремого важкого бекенду: агент = тонкий сервіс.

## 3. Стек
- **Агент:** Claude **Agent SDK (TypeScript)** — нативний MCP-клієнт + tool-loop (найлегше). Альтернатива — Python + Anthropic SDK + MCP-клієнт.
- **MCP:** Silpo MCP (remote, OAuth 2.1+PKCE). Fallback — raw JSON-RPC (перевірений).
- **Канал:** Telegram Bot API (безкоштовно, просто). Голос: Telegram voice → STT (Whisper / провайдер).
- **Планувальник:** cron / Claude Routine / n8n.
- **Стан:** легка БД/файл (SQLite/Redis) — user↔chat, токен, останній план. Токени серверно.

## 4. Компоненти
- **Agent core:** system-prompt (2 наміри + tone-guardrail + safe-default) + інструменти Silpo MCP; легкий детермінований helper для ре-ранкінгу «інгредієнт→SKU» (сирий пошук промахується ~30-40% — див. docs/06).
- **Silpo integration:** OAuth (демо — свій акаунт), resolveContext (branch→deliveryType→**available slot**, docs/06), виклики tools.
- **Telegram bot:** приймає текст/voice → агент → відповідь + inline-кнопки (checkout-лінк). 
- **Scheduler/тригери:** з плану меню — нагадування по часах прийомів («час готувати сирники», «час замовити на завтра»).
- **Notifications:** Telegram (головний). SMS(Twilio)/Viber — roadmap (акаунти+гроші+модерація).

## 5. Наміри агента (capabilities)
1. **Швидкий дозаказ:** «забув купити молоко і хліб» → resolveContext → find_products (ре-ранкінг) → add_or_update_cart → (delivery type/slot/address через update_shopping_cart) → checkoutWebLink.
2. **Меню на тиждень:** бюджет + люди + уподобання + алергії + техніка → Claude генерує меню (з калоріями) → матчинг товарів → список/кошик → checkout. Опції: купувати по днях (щоденні доставки) або одразу на тиждень.
3. **Заміна страви/товару:** «заміни X» → альтернатива під ті самі обмеження → перерахунок.
4. **Тригери:** нагадування готувати/замовити за розкладом плану.

## 6. Фази (2 тижні)
- **P0 · Scaffold агента** — TS Agent SDK проєкт, .env (ANTHROPIC_API_KEY, SILPO_MCP_URL, TELEGRAM_BOT_TOKEN), під'єднати Silpo MCP, довести живий `tools/list`. accept: агент бачить silpo_* tools.
- **P1 · Intent «дозаказ»** — system-prompt + інтент-роутинг; дозаказ end-to-end у тексті → checkoutWebLink. accept: «купи молоко і хліб» → реальний кошик+лінк.
- **P2 · Intent «меню тижня»** — генерація меню (+калорії) → матчинг → список/кошик. accept: меню на N днів у бюджет, реальні товари.
- **P3 · Telegram-канал** — бот (текст) ↔ агент, inline-кнопки [Оформити]. accept: живий бот виконує обидва інтенти.
- **P4 · Голос** — Telegram voice → STT → агент. accept: голосом «дозакажи…» працює.
- **P5 · Тригери** — планувальник шле пуш «час готувати/замовити» з плану. accept: пуш приходить за розкладом.
- **P6 · Ре-ранкінг + хардненинг + demo** — legkий матчинг-фільтр (docs/06), обробка помилок/429/500; demo-контур з видимим JSON-RPC логом. accept: стабільне demo.
- **DEMO-ACC** (людина) — акаунт Сільпо з активним кошиком (+історія для персоналізації).

## 7. Must (2 тижні) vs Vision
- **MUST:** агент + Silpo MCP + **Telegram** + обидва наміри + **1 тригер** + живе demo з видимими викликами.
- **VISION (слайди, не код):** SMS/Viber, мобільний застосунок (прототип AI Studio), підписка/монетизація, партнер Спортмастер, гейміфікація (бали/виклики), мульти-юзер.

## 8. Чесні обмеження
- **Оплата = checkout-лінк**, не авто-оплата в агенті (юзер тапає). Адресу/слот агент ставить.
- **Кошик** не створюється через MCP — активний кошик гостя (docs/06).
- **Проактивні пуші ≠ чистий Claude** — потрібен планувальник.
- **Кожному юзеру** свій Silpo-OAuth; для demo — свій акаунт.
- **Матчинг** сирого пошуку слабкий → легкий ре-ранкінг обовʼязковий (docs/06).

## 9. Demo-план (код не обовʼязковий, але тут дешевий)
